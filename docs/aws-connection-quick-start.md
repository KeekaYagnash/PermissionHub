# AWS connection quick start

Start with read-only connectivity. Enable provisioning only after validation works, and test changes in a non-production account first.

## 1. Recommended IAM Role setup

Create `PermissionHubReadRole` in the target account with a custom trust policy that permits the PermissionHub backend principal to call `sts:AssumeRole`. Use the External ID generated by the configured onboarding workflow, never trust `*`, and keep the External ID out of notes and logs.

In PermissionHub, choose **Add AWS account**, select `ASSUME_ROLE`, and provide the account name, 12-digit account ID, account type, region, read-role ARN, and configured External ID secret reference.

## 2. IAM User local-testing setup

Create `PermissionHubLocal` without console access or a password. Create an access key only when role assumption is unavailable, then configure it on the backend machine using an AWS CLI profile or backend-only environment variables. Never enter AWS credentials in the PermissionHub browser, source code, Git, Vite variables, localStorage, or API requests.

```sh
aws configure --profile permissionhub-local
aws sts get-caller-identity --profile permissionhub-local
```

In PermissionHub, choose `LOCAL_DEFAULT_CREDENTIALS` and enter only account metadata.

## 3. Suggested read policy

The full starting policy is available from the Connection page guide. It permits STS account validation, IAM identity and policy discovery, and Access Analyzer policy validation. Review and reduce it to the actions your deployment uses; many IAM listing operations require `Resource: "*"`.

This starting point is not universally least privilege and does not include `AdministratorAccess`.

## 4. Optional provisioning role

Use a separate `PermissionHubProvisionRole` for approved changes. Restrict it to PermissionHub-managed policy paths and permitted users and roles. Apply permission boundaries where required. Do not enable it until read validation succeeds.

## 5. Validate the connection

Select **Validate connection**. PermissionHub will assume the configured role or use the backend credential chain, call STS `GetCallerIdentity`, verify the account number, and test IAM users, roles, and policies. The connection becomes Connected, Degraded, or Error.

## 7. Security checklist

- Prefer temporary role credentials for production.
- Never use root credentials or `AdministratorAccess`.
- Never store AWS credentials in the browser or repository.
- Keep External IDs in the configured secret-management workflow.
- Validate read access before enabling provisioning.
- Test provisioning in a sandbox account first.
