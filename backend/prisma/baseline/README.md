# Missing initial schema restored

The first historical migration (20260803120000_multi_tenant_auth) alters User,
Request, Approval, PermissionGrant and AuditEvent, but their CREATE statements
were never committed as a migration. The original schema exists in repository
commit **7f453d8**. `legacy.prisma` preserves that exact schema.

`20260801000000_initial_legacy_schema/migration.sql` was generated with Prisma
6.19.3 using `migrate diff --from-empty --to-schema-datamodel
backend/prisma/baseline/legacy.prisma --script`. Its name sorts BEFORE every
existing upgrade. No historical migration was edited, removed or squashed.
Fresh databases now create the original schema, then apply the seven historical
upgrades in order, reaching current schema.prisma. IDs are generated by Prisma,
not hardcoded SQL credentials or seed identities.

This change targets the explicitly confirmed EMPTY dev database. Do not replay
the new initial CREATE migration against an unrelated nonempty database. A
previous deployment with out-of-band/db-push history would require a separate,
reviewed baselining procedure; no such recovery is performed here.

`npm run test:migrations --workspace backend` requires an explicitly provided
MIGRATION_TEST_DATABASE_URL pointing to localhost and a database named
permissionhub_migration_test_*. It refuses nonlocal/application databases and
nonempty databases, applies the full chain twice, verifies status/schema drift,
and tests persistence, FK/unique constraints and cascade behavior. CI uses an
isolated PostgreSQL 16 service; neither the test nor Lambda startup calls db push.
